## 目标数据契约

### 已实现的目录布局

三个分卷使用相同目录骨架。知识部分镜像
`data/game_knowledge/generated-v0.107.1/` 的类别和单实体文件布局，另外增加
`combat/` 与 `strategy/`：

```text
data/datasets/sft/
├── manifest.json
├── behavior-audit.json
├── train/
│   ├── arithmetic/*.jsonl
│   ├── cards/*.jsonl
│   ├── characters/*.jsonl
│   ├── enchantments/*.jsonl
│   ├── encounters/*.jsonl
│   ├── events/*.jsonl
│   ├── keywords/*.jsonl
│   ├── monsters/*.jsonl
│   ├── potions/*.jsonl
│   ├── powers/*.jsonl
│   ├── relics/*.jsonl
│   ├── combat/<run-id>/<battle-key>.jsonl
│   └── strategy/<run-id>.jsonl
├── validation/
│   └── 与 train 相同的目录骨架
└── eval/
    └── 与 train 相同的目录骨架
```

知识文件继续按实体命名，例如三棵目录分别包含
`cards/ABRASIVE.jsonl`；算术按六个稳定题型拆文件。远古者目录不生成。三个分卷中
所有必需知识类别、算术、战斗和战略都必须存在非空 JSONL；任一方面为零就构建失败，
不能用一个空目录冒充覆盖。旧的 `eval/knowledge/`、`eval/test.jsonl`、
`probes_recall.jsonl`、`probes_compositional.jsonl` 和 `entity_holdout.json` 都由
新版树取代。

`manifest.json` 记录每个 JSONL 的路径、行数和摘要，同时按分卷、类别、实体和事实
汇总覆盖。训练器和评测器递归读取相应分卷目录；不会为了机器读取方便，再生成一份
供人无法审查的聚合大 JSONL。

行为行另外保存当时向模型公开的动作名和按状态索引展开的 `legal_actions`。
构建器会拒绝参考动作不在该集合中的 raw 行；`behavior-audit.json` 则按分卷汇总
动作、页面、条件标签和训练对照，并与 manifest 中的同名记录互相校验。

### 三套问法

知识生成不再依赖“按行排序后把最后一个问题留给 dev”这种隐式规则。每个可训练
事实使用可读 `fact_id`，例如 `cards/ABRASIVE/cost`，并显式生成三种用途：

- `train`：可以有多种直接问法和字段定向问法，用于真正学习该事实；
- `validation`：固定一种不出现在 train 的改写，用于选学习率、epoch 和停止点；
- `eval`：固定另一种不出现在 train/validation 的自然改写，只在方案冻结后验收。

三种用途共享同一个规范答案和 `fact_id`，但问题原文必须互不重复。问法由各知识
类别的生成代码明确给出，不在构建时随机抽取，也不通过通用前缀机械制造“伪改写”。
如果某个事实缺少任一用途的问法，构建直接失败。这样既方便编码，也能从
`train/cards/ABRASIVE.jsonl`、`validation/cards/ABRASIVE.jsonl` 和
`eval/cards/ABRASIVE.jsonl` 横向检查同一事实。

算术不复用同一数字改写问题，而由不同随机种子分别生成 train、validation、eval
数值，并用“题型 + 完整计算语义/操作数”的 `case_id` 做跨分卷硬隔离。人类行为
不做问法改写，继续以整局为单位分配到三个分卷，再按战斗和战略目录保存。

### 训练集

训练集不再把 generated 当成可以任意抽掉的普通语料，而按以下规则构建：

1. 除明确排除的远古者和无效/弃用条目外，当前 generated 输出的每个知识实体和
   每个可训练事实都必须进入 train。类别行数上限不能再破坏覆盖。
2. 每个可训练事实至少有一条显式 `train` 问法；适合多问法学习的事实可以保留多条
   直接问法和字段定向问法。生成器必须给事实一个可读身份，例如
   `cards/ABRASIVE/cost`，不要用无意义哈希代替。
3. 构建清单必须直接报告每个类别的候选实体、候选事实、train 覆盖实体、train
   覆盖事实和问法数。只要任何可训练事实漏入，构建就失败。
4. 四个地图怪池文件的全部现有训练问法进入 train，并额外生成各自不与 train
   重复的 validation/eval 问法。
5. 算术不要求背完全部随机数字题，而要求六类题型分层平衡，train、validation 和
   eval 组合题使用不同运算案例。题型包括格挡、能量、斩杀、多段攻击、充能球/集中
   和状态结算。
6. 人类动作继续按整局分卷，不能把同一局的相邻状态拆到
   train/validation/eval。高频 `play_card`、`end_turn` 可以限量，低频动作不能
   因为全局随机抽样被淹没。

“训练集覆盖全部知识”不意味着把验证题和考试题原文抄进 train。train 学全部事实，
validation/eval 用没有在 train 出现过的问法检查能否从新表述召回同一事实。

### 验证集

整个 `validation/` 用于选择学习率、epoch 和是否停止，必须同时包含：

- 当前每个知识类别的未见问法，并保证问题对应的事实已经在 train 学过；
- 六类未见数字的算术题；
- 按整局留出的人类游戏动作，尤其覆盖战斗、卡牌奖励、营火、商店、药水和地图。

validation 不追求与训练集同样大，但不能再允许某个知识类别因为随机 cap 或事实过滤
变成零覆盖。调参只看综合指标和各桶下限，不能只看战斗动作 loss。

### 最终测试套件

最终测试是整个 `data/datasets/sft/eval/`：

- 各知识类别目录覆盖当前全部可训练事实的 `eval` 问法；
- `arithmetic/` 保存与 train、validation 数值都不同的六类最终算术题；
- `combat/` 与 `strategy/` 保存按整局留出的最终人类行为；
- 根 manifest 记录每个类别、实体和事实的覆盖，并拒绝 train/validation 的精确
  问题泄漏。

最终 eval 从当前 canonical/generated 同步重建，删除旧远古者和旧知识口径。它只在
训练方案冻结后运行；不能根据最终结果反复调学习率，否则 eval 就退化成第二个
validation。

## 人类动作与 Harness 问题

### 当前动作分布

当前 train 的典型数量如下：`play_card=600`、`end_turn=160`、`use_potion=57`、
`choose_rest_option=50`、`choose_reward_card=56`、`skip_reward_cards=26`、
`open_shop_inventory=13`，购买卡牌/遗物/药水分别只有 6/6/4 条。

模型对这些人类动作比例非常敏感：少量偏差就可能表现为总在营火休息、总升级、
不喝药、不进商店或总进商店。解决方法不是简单把某个动作复制很多遍，否则只会把
偏差翻向另一边。需要补的是成对、带条件的决策边界样本，例如：

- 同类战斗里“现在喝药能避免大量掉血”和“现在喝药只是浪费”的对照；
- 营火低血量且下个节点危险时休息，与血量安全、关键牌升级收益高时升级的对照；
- 有足够金币且商品提升明显时进入/购买，与没有购买力或商店价值低时离开的对照；
- 卡牌确实改善构筑时选择，与三张牌都会污染构筑时跳过的对照。

卡牌构筑是最难的长期决策。SFT 可以教会局面—动作先验、卡牌与机制知识以及明显的
正反例，但仅靠模仿少量人类局不能可靠学到整局构筑价值；这一部分最终仍需要后续
Tree-GRPO/GiGPO 的同状态分支和长期回报。

### 无状态循环的规则

采用硬屏蔽方案，不继续靠不断增加提示词解决 UI 往返：

1. 卡牌奖励：本次奖励流程一旦执行 `skip_reward_cards`，在离开该奖励流程前隐藏
   同一个卡牌奖励。当前工作树已经实现这条规则，需要保留回归测试。
2. 商店：同一次商店访问中，库存打开后又被关闭，就隐藏再次
   `open_shop_inventory` 的动作，直到真正离开 `SHOP`。模型仍自行决定购买或
   `proceed`，Harness 只禁止没有新信息的反复开关，不替模型购买或离店。
3. 规则状态只在当前奖励/商店访问内有效，屏幕离开后清空；测试要覆盖购买后继续
   浏览、直接离开和下一家商店重新开放。

这相当于正式定义游戏 Agent 的可见动作规则：进入一次性决策后必须选择或放弃，
不能靠重新进入刷新自己的“记忆”。

## E4 五轮异问法知识训练

## no-thinking 输出与 RL 的边界

SFT 只训练和验收最终单行 `ACTION:`：

- no-thinking 回复为空、格式错误、动作不存在或参数越界，都按错误记录；不从
  reasoning 最后一行打捞动作，也不靠重试后只保留成功答案掩盖错误率；
- teacher-forced token accuracy 只能辅助看训练是否收敛，交付必须做真实生成；
- 贪心生成和 temperature 0.8 都要以 `max_retries=0` 测格式/合法动作率。0.8 会
  放大尾部错误，但它暴露的是 RL 真实采样分布，不能只用低温评测回避。

RL 侧负责 thinking、采样温度与失败 rollout：模型产生非法动作时，应保留原始
tokens/log-probs 并给负奖励，而不是不断重采直到合法后只训练合法样本。若以后使用
语法约束解码，也必须保存约束后行为分布的 processed log-prob。这些不要求本轮 SFT
生成 thinking 监督数据。

## LoRA rank 决策

当前 r16 不是一个明显过小的“象征性 adapter”：它有 14,376,960 个 FP32 可训练
参数，并覆盖全部目标 projection。按当前格式估算：

| rank | 可训练参数 | 最终 adapter | adapter + AdamW 精确恢复状态 |
| ---: | ---: | ---: | ---: |
| 16 | 14.38M | 54.8 MiB | 164.5 MiB |
| 64 | 57.51M | 219.4 MiB | 658.1 MiB |
| 128 | 115.02M | 438.8 MiB | 1.29 GiB |

这里的 checkpoint 大小还应给 JSON、随机状态和文件系统元数据留少量余量。r64/r128
会线性增加 LoRA 参数、梯度和优化器状态，但不会让整个 4B 基座的训练耗时严格增加
4 倍/8 倍；长序列的基座前后向和 activation 仍占主要成本。

当前不直接跳到 r64 或 r128，首要原因确实是知识覆盖，而不是已经证实 r16 容量
不足。按本次审计使用的操作性口径，train 只覆盖 422/5,842 个“同类别、同实体、
同规范化答案”事实组，因此未覆盖比例为 `1 - 422 / 5,842 = 92.78%`，四舍五入为
92.8%。这个数字是准确的覆盖审计结果，但不能表述成“92.8% 的原子事实”——一个
长答案组可能包含多个原子字段。无论采用哪种事实粒度，当前大量实体和答案组完全
没进入 train 的结论不变；扩大 adapter 不能学习从未看过的数据。QLoRA 的消融也
指出，当 LoRA 已经覆盖全部 transformer linear 层时，覆盖模块数比单纯扩大 rank
更关键，rank 变化未显示稳定收益。参考：
[LoRA](https://arxiv.org/abs/2106.09685)、
[QLoRA](https://arxiv.org/abs/2305.14314)。

执行决策如下：

1. 先用覆盖完整的新数据继续训练 r16；默认沿用 alpha/rank=2 的缩放关系。
2. 如果 train 知识/算术真实生成仍明显达不到 99%，且 loss 在充分训练后仍高，
   再做同数据、同起点、同优化步预算的 r16 对 r64 小规模 A/B；r64 使用 alpha 128。
3. 只有 r64 明确改善并且仍呈容量不足，才考虑 r128/alpha 256。不能仅因为服务器
   有 A100 就扩大参数。
4. rank 不同的 adapter 不能冒充同一次精确续训；对照实验必须使用独立日期目录并
   清楚记录共同起点。

## 与 CombatSolver 数据主线的合流

## 交付验收线

数据先于模型验收：

- train 对当前可训练知识实体和事实覆盖 100%，四张地图怪池全部覆盖；
- train/validation/eval 的问题原文互不重复，validation/eval 所考事实均能追溯到
  train；
- validation 同时包含所有知识类别、六类算术和整局留出的游戏动作；
- 最终测试不含远古者和废弃知识，且完整覆盖当前知识口径。

模型目标：

- train 上知识与算术的真实贪心生成正确率达到 99%，证明不是容量或优化不足；
- validation 和最终 eval 的未见问法按类别报告，目标宏平均和每个关键类别均达到
  99%；
- 长知识回答除当前严格全文匹配外，还要报告字段/数值是否完整，避免纯粹措辞不同
  被误判为知识错误；不使用 LLM judge 掩盖错误；
- 游戏动作不以“与人类动作逐字一致 99%”为目标，因为同一状态可能有多个合法
  选择；交付线是单行格式正确率、动作合法率和关键场景决策分别报告；
- temperature 0 和 0.8、`max_retries=0` 下都报告格式失败与非法动作。0.8 的目标
  合法率至少 99%，失败不能被重试过滤；
- 药水、营火、商店、选牌/跳过分别做定向场景报告，不能只给一个被高频出牌动作
  淹没的总准确率。

如果某项没有达到目标，先按“数据没覆盖、答案/评分器有误、优化不足、LoRA 容量
不足”的顺序定位，不默认用更大 rank 或更多 epoch 硬压。
